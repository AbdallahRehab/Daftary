# Preliminary Findings (seeds to verify)

**Feature**: [spec.md](spec.md) · **Collected**: 2026-10-05 by reading the code (nothing was executed)

These are observations from a first read of the code. They are **not** audit conclusions. Under FR-003 and SC-005, the audit must mark each one Confirmed, Refuted or Partially confirmed, with evidence.

| ID | Area | Observation | Evidence | Suspected severity |
| --- | --- | --- | --- | --- |
| PF-01 | Logic | The direction of a repayment is worked out automatically from the current balance. Only *they owe you* gives "received". Every other status, **including settled**, gives "given". The UI hides the repayment button when the person is settled. But a repayment that is bigger than the debt, or recorded through another route, silently creates a new debt that is still labelled a repayment. | `lib/features/transactions/data/repositories/transactions_repository_impl.dart` (`_repaymentDirection`); `person_detail_page.dart` (button hidden when settled) | P1 |
| PF-02 | Logic | Editing a repayment opens the same form as an ordinary transaction, which has a given/received switch. A repayment can be flipped to the same direction as the debt, so the debt grows by twice the amount while the row still says "سداد". | `transaction_form_page.dart` (direction switch); `EditTransaction` accepts `direction` | P0 if confirmed |
| PF-03 | Accounting | Occasion contributions count toward the person's loan balance by default. Only condolence contributions are excluded. So a wedding gift received (نقطة) shows as "you owe them", mixed with real loans in "إجمالي المستحق عليك". | `balance_queries.dart` (`counts_toward_balance` filter); `money_transaction.dart` (`countsTowardBalance`) | P1 (policy decision) |
| PF-04 | Accounting | Exchange rates are stored as one current value per currency, with no history. Every balance or total that involves a foreign currency is converted again at today's rate, so changing a rate silently changes historical balances and totals. | `app_database.dart` `ExchangeRates` (no effective date); `person_balance_calculator.dart` | P1 (policy decision) |
| PF-05 | Auditability | An audit history (previous values on edit and delete) is stored and synced, but no screen shows it. The user cannot see why a balance changed. | `TransactionAuditEntries` written in `transactions_repository_impl.dart`; no references under `lib/features/*/presentation` | P2 |
| PF-06 | Terminology | "تمت التسوية" means "net zero balance" for a person, and also "received equals given" for an occasion. These are different ideas with the same label. Occasion "settlement" compares money in with money out across all participants, which is not a settlement in the accounting sense. | `app_ar.arb` (`personDetailSettled`, `occasionSettlementSettled`); `occasion_summary.dart` | P2 |
| PF-07 | Terminology | "أعطيت / استلمت" does not say *why* (a loan, paying back, or a gift). "إجمالي المستحق لك / عليك" is formal accounting wording. Everyday Egyptian phrasing is "ليك عند الناس / عليك للناس". | `app_ar.arb` | P2 |
| PF-08 | Data | A transaction's date is stored as local-midnight epoch milliseconds. With sync across devices in different time zones, or across Egypt's daylight-saving changes, the shown date could move by a day. | `_dateOnlyMillis` in `transactions_repository_impl.dart` | P2 |
| PF-09 | Logic | A repayment is not linked to the debt it pays. Balances are one running net per person. That is correct for "how much is owed", but the app cannot say *which* debt is still open, or how old it is. | `MoneyTransaction` has no settles/linked id | P3 (design note) |
| PF-10 | Docs | `PRODUCT.md` still says "no backend, sync, account" and lists occasions, OCR, budgets and savings as not built. All of them are shipped. | `PRODUCT.md` Operating Context | P2 (source of truth drift) |
| PF-11 | Sync | The client logs push conflicts and has a conflict-resolution UI. The audit must check that every financial entity type is covered and what the user sees for a conflict on a transaction. | `sync_engine.dart` `_logResults`; `cloud_sync/presentation/widgets/conflict_resolution_sheet.dart` | TBD |
| PF-12 | Logic | Archived people with a non-zero balance are counted in the overview totals (by design, 001 Clarifications). The audit must check that the user can see where that part of the total comes from. | `overview_summary.dart` doc comment | P2 |
