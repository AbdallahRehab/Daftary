# Decisions: Phase 2c — parser engine (T041-T054, T164)

Slice: HMAC hasher, normalizer, frozen fingerprint normalizer, masker, splitter with envelope rules, profile structures, rule-based engine with the generic profile and registry, `suggestFor`, corpus harness, and the noise/paste/cross/hostile/envelope fixtures. Pure Dart. No injectable annotations (DI is T069). No build_runner needed.

- lib: `data/crypto/hmac_fingerprint_hasher.dart`; `data/parsing/{sms_text_normalizer, fingerprint_normalizer, sms_masker_impl, sms_envelope_rules, sms_message_splitter, sms_template, bank_profile, sms_currency_table, sms_amount_reader, sms_date_reader, generic_profile, sms_parser_registry, select_parse, suggest_for, rule_based_sms_parser}.dart`.

- fixtures: `test/fixtures/sms/{_noise (16), _paste (14 + envelopes/13), _cross (3), _hostile (18)}`, `_versions.json` (`{"generic":1}`), `_fingerprints.json` (64 entries).

## Decisions

| # | Conflict or ambiguity | Choice | Why |
|---|---|---|---|
| 1 | "FingerprintNormalizer imports only NumeralParser" vs. it must implement the domain port for DI | One frozen file, `FingerprintNormalizerV1 implements FingerprintNormalizer`. Its imports are `numeral_parser.dart` and the domain port, which has no imports and no behavior. The import guard (golden test) pins exactly those two imports and checks that the port and `NumeralParser` import nothing. An earlier separate adapter file was removed at the coordinator's request ("exactly one frozen normalizer"). | It keeps one frozen file with no parser dependency. The only extra import is an import-free interface. |
| 2 | `\s` semantics for the frozen whitespace collapse | An explicit code-unit list (tab..CR, space, U+0085, U+00A0, U+1680, U+2000-200A, U+2028/2029, U+202F, U+205F, U+3000) instead of RegExp `\s` | A frozen function must not depend on regex engine semantics. |
| 3 | Arabic folding "ؤ/ئ conservatively"; harakat range | `ؤ`→`و`, `ئ`→`ي`; also strips U+0670 (superscript alef) along with U+064B-065F | Folding is applied the same way to rules and text, so it is symmetric. U+0670 is a diacritic. |
| 4 | Index map for display text | `normalizeWithMap` returns a folded→display map. Lower-casing is applied only when it keeps one code unit, so the map stays 1:1. Dart gives no group offsets, so a template group is located inside the whole match. A repeated occurrence is equal after folding, so content is never wrong. | Merchant names are shown as the bank wrote them (contract §3). |
| 5 | Masker: FR-031a joins groups across spaces, but T044 requires `EGP 1500 01012345678` to mask only the mobile | Mobiles are masked first. A contiguous mobile has digit-only boundaries. A spaced mobile has strict boundaries (no digit group joined across a separator). Then come long runs joined by a single space or hyphen. A spaced card with a mobile-shaped block is masked as a whole card. | Satisfies both: the amount survives, and a card never leaks more than 4 digits. Digits are one UTF-16 unit each, so the shadow index map is the identity. |
| 6 | Threshold "lowered, never raised" | `mask` clamps above 12. `BankProfile` clamps `maskThreshold` too. | FR-031a. |
| 7 | CHK045 separators | Validated in `SmsAmountReader` before `CurrencyFormatter.parse`. A comma is valid only in a `\d{1,3}(,\d{3})+` shape and a space only in a `\d{1,3}( \d{3})+` shape. `1 500,00`, where the space join is refused, is detected as a broken group and is unreadable, never `1`. Zero is unreadable. `FormatException` is caught and never copied. | Never a silently wrong amount. Residual risk: `EGP 100 200 300` reads as 100200300 (space grouping is required by the briefing). Recorded. |
| 8 | Amount with no stated currency (generic or paste) | `amount = null`, `amountCandidatesMinor = [minor]` (one candidate), currency field absent, so overall is Low (D-C1). No `ambiguousAmount` warning. All catalog currencies have 100 minor units (asserted by a test). | `ParsedTransaction.amount` is `Money?` and cannot hold a number without a currency. FR-035 makes currency a user choice. **Flag for the review owner (T078/T082): one candidate plus no currency means "pre-fill amount, pick currency".** |
| 9 | Stated currency outside the catalog | `amount = null`, no candidates, `currencyCodeRead` set, `unsupportedCurrency`. The token's structure is still validated (up to 3 decimals). A non-catalog ISO code is recognized only when written upper-case in the original. | FR-053: the number is never reinterpreted. Upper-case only avoids `try`, `all`, `top` and `pen` as false codes. A bare `£`, `ريال` or `درهم` maps to no currency (ambiguous). |
| 10 | Several money tokens (generic) | Each token is tagged by the nearest preceding keyword in the same sentence (40-char window): balance/limit → excluded, fee → fee, otherwise primary. Any malformed primary → `amountUnreadable`. Several distinct primaries of one currency → ambiguous with candidates. Mixed currencies → ambiguous, no candidates. Only fee tokens → kind `fee`. | FR-030. Conservative: never picks one value silently. |
| 11 | Year inference: contract (received year) vs briefing CHK050 (AppClock) | Briefing: current year from the injected clock, or the previous year when the date is more than one day after now. Applies to scans too. | Binding decision. With the 90-day scan window it gives the same answer as the received-year rule. |
| 12 | Year-less numeric `d/m` | Accepted only after a date keyword (`on`, `date`, `في`, `بتاريخ`, `يوم`) or before a time. Templates accept it directly. | `1/12` installments would otherwise become dates. |
| 13 | Received-time date (FR-038) | `receivedAt.toLocal()` calendar day, inferred. A stated date always wins. | Tests cover Egypt's DST nights and a UTC instant. |
| 14 | Unverified bank profiles | `BankProfile.verified` (default false). A non-generic unverified profile caps overall at Medium and adds the new `SmsWarning.unverifiedProfile` (`unverified_profile`). The generic profile is capped anyway and gets `genericParser`. | Orchestrator decision. No existing warning fits; **the UI (T066/T082) needs copy for it.** |
| 15 | "Purchase at authorization" (FR-024b) | `SmsTemplate.postsAtAuthorization`: such templates are tried before the generic pending-authorization rule (after the profile's own pending rules). | Calibrated per bank, as the contract says. |
| 16 | Step 3 vs step 4 ordering (`authorization reversed` contains `authorization`) | Generic pending authorization applies only with no posted verb, no reversal phrase and no refund phrase. Reversal applies only with no refund phrase (refund wins when in doubt). | Contract §5. |
| 17 | `NotRecognized` vs `Unreadable(noAmount)` | No generic vocabulary (no kind rule, no posted verb) → `NotRecognized`. Vocabulary but no amount → `Unreadable(noAmount)`. Bank-profile failures return `Unreadable(noAmount, bankId)`, and `selectParse` gives generic a last try. `amountUnreadable` never gets a second opinion. | FR-018, contract §7.5. |
| 18 | Generic direction | Kind rules in priority order (refund, own account, card settlement, salary, ATM, bill, transfer in, transfer out, purchase) fix kind and direction. If the posted verbs only contradict it, the result is kind and direction unknown (FR-033). Debit plus credit verbs with no rule → unknown. Generic direction is read at Medium. | Conservative: an unknown direction disables Add. |
| 19 | Learned mappings and archived categories | Added `ParserOptions.activeCategoryIds`. A learned id is used only when it is in that set or among the active seed ids, so with the default (empty) set no learned mapping applies. Archived or missing seeds fall to the next step, then to none. | `ParserOptions` had no way to know whether a learned target was archived (T051 test "archived mapping skipped"). **T062/T069 must pass the active ids.** |
| 20 | `merchantKey` for transfers | Derived from the merchant, else the counterparty (folded, letters only, collapsed). | Lets a learned mapping apply to a named transfer. |
| 21 | Privacy of names | Merchant and counterparty mask any run of 5+ digits to its last four and are capped at 120 characters. `last4` patterns refuse a 4-digit block followed by more digits (never the first 4 of a full card). The reference is transient and `toString` is redacted. | FR-031, invariant 2. |
| 22 | Splitter bound order | The raw input length (UTF-16 units) is checked before anything else. | Stricter than strip-then-measure, and consistent with the Kotlin 10,001-unit truncation. |
| 23 | T047 depends on T014 (S5 spike not run) | Implemented against the UNVERIFIED S5 table (E0-E5 plus safety rules), `SmsEnvelopeRules.version = 1`. Marked [X] because its tests pass. Every envelope fixture carries `"unverifiedFormat": true`. **Device verification is still owed (T163/T014).** | Briefing. |
| 24 | E1 sender shape with no bank profiles registered | E1 accepts registered senders and short-code/phone shapes. An unregistered upper-case `[A-Z][A-Z0-9._-]{1,10}` (SMS sender-ID limit) is accepted only directly before a date/time line (E1E2), or with a stamp on the same line (E3). E4 brackets accept a stamp plus `SENDER:` or a short sender or contact name. A header inside a chunk splits only when it matches the chunk's first header shape. | Under-strip on doubt, while the assumed Samsung and Google header formats still work before bank profiles exist. A safety rule 2 conflict is noted: a future profile signature matching its own sender ID would stop E1 stripping for that bank. |
| 25 | Fixture folders | Reversal and in-message-fee cases live in `_paste/` (source paste) because there are no bank folders yet. `_cross/` holds spoofed-sender, unsupported-bank and look-alike cases that must fall to generic. The per-bank SC-001 gate and the cross-bank invariant loops run, but are vacuous until bank folders exist. | T053/T054; bank profiles are a later phase. |
| 26 | Golden update path | `SMS_FINGERPRINTS_ADD_MISSING=1` appends entries for new fixtures only. It never rewrites an existing entry, so any change to the frozen output still fails. Checked by mutation: dropping digit normalization fails the golden test. | Keeps the freeze while letting the corpus grow. |
| 27 | Regex safety | Every engine pattern is bounded with no nested quantifiers. A test runs each on seven 10,000-character adversarial strings (< 50 ms each), runs whole-message hostile parses (< 500 ms), and runs 400 seeded random strings (never `parserError`, deterministic). Keywords use linear substring search. | Contract §2 rule 2, FR-098. |

## Convergence fixes (P1–P11)

Each fix has a test written first under `rule_based_sms_parser_test.dart`, group `convergence fixes (P1-P11)`. Every case used only synthetic text, and each test was seen failing for the reason the audit gave. Every audited item reproduced.

| # | Change | Files |
|---|---|---|
| P1 | `roleAt` now walks back to the nearest real sentence end. A `. ` after an abbreviation (bal, avl, avail, amt, a/c, acc, no, ref, txn, …) is no longer treated as a stop, so the balance in `Avl. Bal. EGP …` is tagged balance. A message with only a balance now gives `Unreadable(noAmount)`. A balance next to a real amount is no longer offered as a candidate. | rule_based_sms_parser.dart |
| P2 | The Arabic comma U+060C between digits is scanned as part of the token and validated exactly like `,`. `1،500` reads as 1500. `1،50` is `amountUnreadable`. It is never 500. | sms_amount_reader.dart |
| P3 | Promotion is split into two sets. The strong marketing set (offer, discount, %, عرض, …) counts with no posted verb, as contract §5 says. The weak set (visit, www, http, deal, enjoy) counts only when no kind rule matched either. Arabic promo words must start a word or follow an attached clitic, so `عرض` no longer matches inside `معرض`. **Deviation from the audit's wording:** a strong marketing word still wins over a kind rule, because contract §5 makes "installment-offer" text a promotion (`0% installment on purchases above EGP 1,000. Offer …`). | generic_profile.dart, rule_based_sms_parser.dart |
| P4 | Tokens that the card last-four patterns capture are never money tokens. Posted English verbs (debited, credited, charged, …) were added as amount lead words. | both |
| P5 | The strong OTP words alone mean OTP. The weak words (do not share / never share / لا تشارك / bare رمز, كود, code, pin) mean OTP only together with a standalone 4–8 digit code: no currency next to it, not a last four, not a 19xx/20xx year. Added رمز التحقق, كلمة المرور لمرة واحدة, one-time code and similar. | both |
| P6 | The decline rule is skipped when a refund or reversal phrase appears together with posted-refund wording (refunded, has been credited, credited to your, تم استرداد, …). A future credit (`will be credited`) still counts as declined, the conservative reading. Bare credit verbs alone were not enough. | both |
| P7 | New step 5b: due or reminder vocabulary (reminder, is due, due on/by, total due, amount due, تذكير, مستحق, موعد السداد, …) with no posted verb gives `NonTransactional(other)`. This uses the existing enum value, so no domain change was needed. `statement` and `كشف حساب` were left out on purpose: the corpus has statement-fee debits (aaib/qnb `fee_*`). | both |
| P8 | Added the تمت forms: تمت إضافة, تمت عملية إيداع/إضافة/سحب/خصم/دفع, and also تم الدفع. Folding already merges إ/أ/ا and ة/ه. | generic_profile.dart |
| P10 | `KeywordSet` gained the `arabicWordStart` and `arabicWordEnd` options (start allows the clitics و ف ب ل ك ال and their combinations) and `KeywordSet.merge`. The default behaviour is unchanged. `مدين` is now a whole word. The feminine debit phrases عملية/حركة/معاملة مدينة were added explicitly, so `فرع مدينة نصر` is no longer a debit. | sms_template.dart, generic_profile.dart |
| P11 | A year-less `<day> may` followed by a verb (apply, be, vary, …) is not a date. The pattern was added to `patternsForTest`. | sms_date_reader.dart |
| P9 | Skipped, as instructed. | — |
