| 12 | **Sync mapper round-trip tests (outside my slice, minimal edit)** | `money_transaction_sync_mapper_test.dart` (2 cases) and `finance_entry_sync_mapper_test.dart` (1) compared `fromWire(...)` with `row.toCompanion(false)`. | 13 | T039 "registered under its own DI name" vs discovery/di.md | No DI registration and no `@Named`. `SecureStorageSmsKeyStore({FlutterSecureStorage? storage})` defaults to its own `static const defaultStorage = FlutterSecureStorage(aOptions: AndroidOptions(resetOnError: false, storageNamespace: 'daftary_sms_import'), iOptions: IOSOptions(accessibility: first_unlock_this_device))`. **T069**: annotate the class `@LazySingleton(as: SmsKeyStore)` and put `@ignoreParam` on `storage`, so the shared `FlutterSecureStorage` singleton is never injected into it. | discovery/di.md (preferred option). The namespace isolates the Android prefs, KeyStore alias and wrapped key, so a reset of the shared instance cannot erase the SMS keys, and nothing here can erase the PIN hash, session or AI key. |
| 14 | "Any storage error maps to key unavailable" vs research "key loss → new key generated on next use" | A failing call throws `SmsCryptoException(keyUnavailable)`, is never cached, and **never overwrites** the unreadable entry, so a transient error loses nothing (tested). If the **next use** in the same process still cannot read the key, the key counts as lost: only that one entry is deleted and replaced by a fresh, read-back-verified key (tested; other entries untouched). Concurrent callers join one in-flight load and share its result or failure, so a burst of calls counts as one use. An absent key, or a malformed one (bad base64 or wrong length), is replaced at once. | Without a recovery step, a persistent read failure (for example after an Android Auto Backup restore) would block ingestion forever, because fingerprints need the MAC key. Recovering on the first error would turn every transient glitch into data loss. Whether a write succeeds on Android once the namespace's wrapped key is unreadable can't be checked here (no device). If it doesn't, the store stays "unavailable" (safe, nothing destroyed). This is a device-verification item. |
| 15 | Single flight vs purge | Loads and purges run through one in-store queue. `purge()` waits for any load in flight, clears both caches, tries **both** deletes even if one fails, then throws a content-free `keyUnavailable` if either failed. It never calls `deleteAll` (the test fake fails if it is called). | "No key outlives a purge", and Delete-all can never touch other features' secrets. |
| 16 | What the key store and vault throw | New `lib/features/sms_import/data/crypto/sms_crypto_exception.dart`: `SmsCryptoException(SmsCryptoError.{keyUnavailable, sealFailed})`, whose `toString` is the code only. Underlying platform or cipher messages are always dropped. | Briefing rule 6 (nothing in exceptions). The domain port only says "exceptions mean treat as purged". The HMAC hasher (other agent) can catch it or any error. |
| 17 | Vault `seal` failure modes | Lost or wrong-length key → `keyUnavailable`. Empty AAD, wrong-length nonce hook or cipher error → `sealFailed`. `open` returns `null` for every unreadable case (short blob, version ≠ 0x01, key missing or wrong length, tag failure, AAD mismatch, non-UTF-8 plaintext) and never throws. | Matches the domain port. An empty AAD is refused so that every blob is bound to a row id. |
| 18 | "Fixed-key/nonce test hooks" | The key is fixed through an `SmsKeyStore` fake. The nonce is fixed through the `nonceForTesting` constructor parameter (production passes nothing, so `Random.secure()` is used). `@visibleForTesting static gcmForTesting(...)` exposes the raw primitive. **T069**: put `@ignoreParam` on `nonceForTesting`. | — |
| 19 | Fixed vectors | (a) The full blob for a synthetic Arabic and English message, compared with an **independent** implementation: Apple CryptoKit `AES.GCM.seal`, run once via `swift` on this machine with key 0x00..0x1f, nonce 0xa0..0xab and AAD = a fixed pending id. (b) The primitive checked against McGrew & Viega GCM test case 16 (AES-256, 96-bit IV, AAD). Both pass. | A golden value computed only by our own code would pin regressions but prove nothing. |
