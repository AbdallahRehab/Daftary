# Decisions: Phase 1 spikes (T010-T013, T163), addendum (T014), pointycastle (T015)

1. **Spikes not run.** No physical devices or emulators are available, so S1-S5 were documented as "NOT RUN — device required" with the designated default, the fallback, and a device checklist (`spikes/S1`-`S5`). T010-T013, T163 and T014 stay `[ ]` (AGENT_BRIEFING "Device spikes S1-S5").
2. **S3 is not strictly a device spike.** It needs only an Android SDK Gradle build. Per the orchestrator's grouping it was still left as not run. S3 notes this so it can be run on any workstation or CI runner.
3. **T014 acceptance vs. no run.** T014 requires the addendum to "not leave any of them open". Without device runs, the addendum states each item as a *default pending device verification*. OQ5 and OQ6 are explicitly left **open release gates** (owner-only), because claiming an answer would be fabricated. No decision is overturned, so `contracts/sms-platform-channel.md` §2.4 is unchanged.
4. **S5 envelope table.** Formats are best-known assumptions labeled UNVERIFIED, using placeholders only. Conservative reading for the splitter (T046/T047): E1-E3 header lines are stripped only in header position, lines with a currency token or a profile signature/`messageStart` are never stripped, and an unknown shape is left alone (under-stripping is the safe failure, because duplicate tiers 2-3 still catch it; over-stripping could drop body text such as a date on its own line). Shape matching uses a shadow copy with bidi/zero-width marks removed and digits normalized, so the RTL marks that messaging apps insert do not defeat the rules.
5. **S3 merged-manifest path.** Recommend that T105 locate the merged manifest with `find` under `app/build/intermediates/merged_manifest/release/` so an AGP layout change fails loudly rather than passing silently.
