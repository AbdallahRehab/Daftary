## Decisions

| # | Doc conflict or ambiguity | Choice | Why |
|---|---|---|---|
| 1 | T063 says `Unavailable*` is "registered on iOS and macOS only, never on Android", but `PlatformSmsInboxGateway`/`PlatformSmsPermissionService` (T107) and `PlatformSharedTextSource` (T095) do not exist yet | `SmsPlatformModule` (the discovery di.md mechanism, `dart:io Platform.isAndroid` plus a pure `selectForPlatform`) is in place. **For now its Android branch also returns the `Unavailable*` adapters**, as the module doc states. **T095 and T107 must each replace their Android branch**; nothing else changes. | Without a native `SmsPlugin`, a `Platform*` adapter would hit `MissingPluginException` and report "unavailable" anyway, so the behaviour is identical and safe. The other choice, leaving the ports unregistered, would break any later resolution. No adapter class carries an annotation, so nothing is registered twice. |
| 2 | Parsing classes (2c) need DI, but the frozen `FingerprintNormalizerV1` may import only `NumeralParser` + its port (guarded) | New `data/sms_parsing_module.dart` (`@module`) registers the parser, normalizer, masker, splitter and frozen normalizer by port. No parsing file was edited. | Keeps the frozen-file import guard and the 2c files intact. |
| 3 | Crypto DI (2b follow-ups) | `@LazySingleton(as: SmsKeyStore)` with `@ignoreParam storage`; `@LazySingleton(as: RawTextVault)` with `@ignoreParam nonceForTesting`; `@LazySingleton(as: FingerprintHasher)`. Annotation and import lines only. | As prescribed. The shared `FlutterSecureStorage` is never injected into the key store. |
| 4 | Tier 2 (`refAmountHash`) for banks whose references are not unique needs "a date within one day" (FR-059b), but `findKnown` returns sets only and tombstones keep no date | New domain port `BankReferencePolicy.refIsUnique(bankId)` (data: `RegistryBankReferencePolicy` over the shipped profiles; generic/unknown → false). `insertPending` treats a reference-amount hit as known only for a unique bank, or for another **pending** row dated within one calendar day. A tombstone hit never collapses a non-unique bank's message. Ingestion sends only unique-bank hashes to `findKnown`. | "A reference ID alone MUST NOT collapse messages." Under-collapsing is safe: the probable rule still warns at review. |
| 5 | The `SmsDuplicateLookup` port had no way to do several FR-059b/FR-051d/FR-024b steps (exclude self from exact matches, find opposite pending items, reversal by reference, bank of a saved SMS record) | Added four read-only methods additively: `findKeyMatches`, `findPendingWithAmount`, `savedRecordsForRefHash`, `bankForSavedRecord`, plus the value type `ImportKeyMatch`. `FakeSmsDuplicateLookup` gained matching scripted fields. | The use case stays pure, and every check is testable with fakes. |
| 6 | CheckDuplicates details | (a) It uses only the **draft's** amount, currency, date and type. A field the user cleared means nothing to compare; an unsavable type falls back to the parsed direction group. (b) Tier 2 applies only while the draft's money and direction group equal the parsed ones, because the hash was computed from them. (c) Tier 3 is per candidate: an SMS-sourced saved record whose tombstone `refHash` is present and differs is skipped. If that leaves nothing probable, the result is `legitimatelySimilar`. (d) Reversal: returns tier `none` with `matchedRecord` set (reference first, then the same amount within one day, money-out records only), so it never blocks or counts as a duplicate. (e) Own transfer: transferOut ↔ transferIn/otherDeposit, opposite direction, same `Money`, within one day, different `bankId` (InstaPay is its own bank id); saved side needs `importSource == sms` and a tombstone bank that differs. (f) Ranking: shared words (≥3 letters, Unicode) between merchant/counterparty and the record note, then the closest calendar day, then the id. (g) A lookup failure is returned as `Left`; it is not swallowed. | Most conservative readings. A failed lookup must not silently skip the duplicate check. |
| 7 | `DuplicateRecordRef` had nothing to rank "merchant/note similarity" by | Added optional `note` (in `props`, never in `toString`). | Needed for analysis M4; additive. |
| 8 | data-model persists `foreignAmountMinor`/`foreignCurrency` for FR-059, but the entity had no field (flagged by 2a #7) | Added `Money? foreignAmount` to `PendingSmsImport` and `ReparsedFields` (additive, in `props`), stored inside `warnings_json`. Test helpers `pendingWithDecision` and `buildPendingImport` pass it through. | CheckDuplicates needs it. |
| 9 | "Each page is committed together with its cursor advance": the cursor lives in the settings repository and there is no cross-repository transaction in the domain | `ingest(..., advanceCursor: true)` advances the cursor to the page's highest `(receivedAt, providerId)` only **after** every message of the page was stored and only when not cancelled. The repository refuses to move it backwards. | A crash between the inserts and the cursor write means the page is read again, and fingerprints make that idempotent. It never skips a message. |
| 10 | Cancellation "between messages keeps the items already created" with a page-level `findKnown` | Cancellation is checked between messages while parsing and hashing. Every message handled before the cancel is then stored (that step is bounded by the page size). `processedBeforeInterruption` = handled messages. | A cancel never discards finished work and never splits a message from its fee item. |
| 11 | Hostile input vs. systemic failure | Per message: a parser throw → `Unreadable(parserError)`; a masker throw → stored without an original; an entity-rule violation (including the debug-mode constructor assert) → `parserError`, nothing stored. A hasher/key-store throw is systemic → `Left(CacheFailure('sms_import_keys_unavailable'))` and nothing stored. A store failure from `insertPending` → `Left`, and items already stored remain. | FR-098 covers one bad message. Without the MAC key nothing can be staged safely. |
| 12 | `NotRecognized` has no `ScanSummary` counter | Added to `skipped` (`SkipReason.notRecognized`) and counted in `scanned` only. | The summary type is from 2a. `ImportPastedText` (T088) derives "not recognized" from `createdPending == 0`. |
| 13 | Masking threshold per profile (`BankProfile.maskThreshold`) is not visible to the domain | Ingestion masks with the default 12. The repository re-masks with the default before sealing (idempotent, defence in depth). | Only the generic profile exists (threshold 12). **Flag for bank-profile tasks (T110+)**: if a profile lowers its threshold, expose it (for example on `ParsedTransaction`) and pass it here. |
| 14 | Parser options need active categories but SC-002 forbids `FinanceRepository` | New `LoadParserOptions` reads `SmsImportSettingsRepository`, `CategoryRepository` (not `FinanceRepository`) and `PeopleRepository`. Seed keys come from the `seed_<key>` id convention, pinned by a test against the real first-launch seed. Archived categories are excluded, and `activeCategoryIds` is passed (2c #19). | Read-only, and keeps invariant 1. |
| 15 | Fee item suggestion (domain cannot call `suggestFor`) | Fee item: kind `fee`, direction debit, `expense` with the active `other` seed category, warning `feeFromMessage`, the parent's confidence, no reference hashes, `parentImportId` = the parent's new id, fingerprint from `feeFingerprint` (2c follow-up). The same masked original is sealed for both. | FR-030a. |
| 16 | "Strict mock asserts zero calls to TransactionsRepository/FinanceRepository" while the service has no such dependency | The test builds the **real generated DI graph**, swaps both repositories for mocktail mocks (plus an in-memory DB and a fake key store), ingests three messages, then runs `verifyZeroInteractions` on both and checks the record tables are empty. | This proves invariant 1 for the wired graph, not just the class. |
| 17 | Decision methods of `SmsImportRepository` belong to later stories | `confirm`, `ignore`, `closeAsDuplicate`, `undo`, `expireDue`, `purgeDecided`, `replaceParsedFields` return `Left(UnknownFailure('sms_import_not_available'))` and write nothing (tested). The shared write path `transitionRow` (`@visibleForTesting`, status guard re-read inside one transaction, always nulls `raw_blob`, `ImportAlreadyDecidedFailure(current)` on an illegal move) is ready for them. The scrub (`confidence_json = '{}'`, 2b #4) belongs to those tasks, because only they know which columns to keep. | The T058 scope. The guard is pure (`canTransition`) and fully tested. |
| 18 | Settings singleton "created on first read" (contract) vs. NotificationPreferences | Reads return defaults and create no row; the first write creates it (tested). | discovery P2, 2b #6. |
| 19 | `SmsChannelClient` shape | Typed per-method calls returning `Either`. Only `PlatformException.code` is read (never message or details). Unknown or malformed → `UnknownFailure('sms_channel_failed')`; `MissingPluginException` → capability unavailable; `permission_denied`/`no_activity`/`request_in_progress` → `SmsPermissionFailure(denied)`. Shared-text stream drops errors and malformed events. | Contract §3. Adapters (T095/T107) add argument validation and the `readSmsDeclared` short-circuit. |
| 20 | `UnavailableSmsPermissionService.openAppInfo` | `Right(unit)`, a no-op. | Contract §6: "every method returns unavailable / Right without a channel call". |
| 21 | `InMemoryScanCoordinator` extra cases | Two explicit scans queue. A scan whose own token was cancelled while waiting does not run (returns `null`). A body error propagates and always frees the slot. | FR-013 plus robustness. |
| 22 | Error copy (spec error table) | 21 keys, one per row plus the per-failure codes. Fixed limits are written in the copy ("10,000 characters", "50 messages"), not as placeholders, so the digits stay Western (FR-090). The only plural (`smsImportErrorScanInterrupted`) has EN `=0/=1/other` and the full AR six forms. `failure_message.dart` gains one `SmsImportFailure()` arm placed before the `_` fallback. Existing arms are unchanged (tested). | ui-contract §5; Arabic in the MSA register of the existing `error*` strings. |
| 23 | Parity-test placeholder check (discovery-t007-t009 #2) | Placeholders come from `@key.placeholders`. Plural and select category sets are parsed at ICU depth 1, with a positive control on `savingsOverviewGoalCount`/`syncStatusPending`. It also fails when an AR string equals the EN string. | Avoids the broken `\{(\w+)` clone. |
| 24 | Hardcoded-string guard scope | `Text('…')` plus `semanticsLabel`/`tooltip`/`labelText`/`hintText`/`helperText`/`errorText`/`label`/`title`/`message` literals under `sms_import/presentation`, comments skipped, with a positive control. | ui-contract §7 requires localized semantics. |
| 25 | Static guard false positives (`fingerprint(` contains `print(`) | Dart: `(^|[^\w.])print\(`, `debugPrint(`, `debugPrintStack(`, `developer.log`, `\bLog\.`, `dart:developer`. Kotlin: `println(`, `printStackTrace(`, `System.out/err`, `Log.`, `Timber.`. Telemetry: a list of analytics/crash packages. Missing Kotlin files are skipped. | T067. |
| 26 | `withinOneCalendarDay` used by data and domain | New pure `domain/rules/calendar_days.dart` (UTC calendar-day difference of the local y/m/d). | Calendar arithmetic, never `Duration` math (DST-safe). |
